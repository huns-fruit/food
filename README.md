## 화면 구성 (업소용 도매몰 톤)

- **사업자 입장 게이트** — 처음 들어오면 딥 네이비·골드의 ‘사업자 전용 입장’ 화면이 먼저 나옵니다. 상호·사업자등록번호·사업자등록증 사진을 확인해야 가격과 품목이 열립니다.
- **맨 위 안내 띠** — 아주 진한 네이비(`#0B1220`) 띠에 식자재 전용몰 안내와 일반몰 링크(`#FCD34D` 밑줄).
- **헤더** — 네이비 그라데이션 고정 헤더. 상호·지점·‘식자재 전문’ 배지와 전화 버튼, 확인한 상호와 **사업자 변경** 버튼, 흰색 검색창.
- **히어로 카드** — 둥근 네이비 카드에 `원주 시내권 배달 · 대용량 업소용 · 채소 50,000원 · 과일 100,000원` 네 칸과 낮 12시 마감 안내(마감 후에는 노란색).
- **탭** — 흰 알약 안의 세그먼트. 선택한 탭만 네이비로 채워지고 품목 수는 노란 배지.
- **상품 카드** — 흰 카드(둥근 모서리 + 옅은 그림자)에 사진·규격 칩·상품명·가격·담기 버튼. 인기 품목에는 빨간 **인기**, 업소에서 많이 찾는 품목에는 네이비 **업소추천** 꼬리표가 사진 위에 붙습니다.
- **주문 안내·사업자 정보** — 흰 카드와 흰 바탕으로 정리해 신뢰감을 주고, 약관 시트는 아래에서 올라옵니다.

`index.html` 의 상품 화면 맨 위(헤더 위)에 식자재 전용몰임을 알리는 띠가 있습니다.

> **식당·카페 대용량 식자재 전용 주문몰** · 가정용 소매는 일반몰을 이용해 주세요

‘일반몰’은 소매몰(https://huns-fruit.github.io/)로 연결됩니다. 띠는 390px 폭에서 한 줄로 들어가고, 그보다 좁은 화면에서는 두 줄로 자연스럽게 줄바꿈되며 가로로 넘치지 않습니다.

## 사업자 전용 입장 게이트 (`js/gate.js`)

B2B 도매몰이라 **사업자 확인 전에는 상품·가격을 보여 주지 않습니다.**

- **처음 방문** — 상품 목록·가격·검색창·장바구니 바를 DOM 에도 만들지 않고, 딥 네이비·골드의 `사업자 전용 입장` 화면만 보여 줍니다. 가정용 손님이 잘못 들어오면 **일반몰로 이동**(`https://huns-fruit.github.io/`) 버튼으로 바로 나갈 수 있습니다.
- **입력 항목** — 상호(가게 이름, 필수) · 사업자등록번호 10자리(필수, `000-00-00000` 자동 포맷) · 사업자등록증 첨부(필수, `image/*`, 파일명과 썸네일 미리보기).
- **번호 검증** — 국세청 체크섬(가중치 `1,3,7,1,3,7,1,3,5` + 9번째 자리×5의 십의 자리, `(10-합계%10)%10` 이 마지막 자리와 같은지)으로 확인하고 `000-00-00000` 같은 번호는 막습니다. 틀리면 번호 칸 아래에 안내문이 붙습니다.
- **저장** — 통과하면 `localStorage['hoonie_bulk_biz_v1']` 에 `{ bizName, bizNo, bizCertName, bizCertAttached: true, verifiedAt }` 만 저장합니다. **사진 데이터는 저장하지 않습니다.** 다음 방문부터는 바로 상품 화면이 열립니다.
- **사업자 변경** — 헤더 띠의 `사업자 변경` 을 누르면 게이트로 돌아가고, 확인했던 상호·번호가 미리 채워집니다(사진은 다시 첨부).
- **주문서 연동** — `상호` 와 `사업자등록번호` 칸이 자동으로 채워지고, 현금영수증을 `사업자번호(지출증빙)` 로 고르면 번호까지 채워집니다. 주문 `data` 에는 `bizNo` · `bizCertName` · `bizCertAttached: true` 만 가볍게 들어갑니다.

### 이용 제한 사업자 (코드 명단 + 사장님 페이지 차단 목록)

두 곳에서 막습니다.

1. **`js/core.js` 의 `BLOCKED_BIZ`** — 코드에 적어 두는 기본 명단(10자리, 하이픈 없이, 기본값 `[]`).
2. **DB `bulk_blocked_biz`** — 사장님이 사장님 페이지에서 등록·해제하는 명단. 번호는 손님 화면에 보이지 않고, DB 함수 `is_bulk_biz_blocked()` 가 `true/false` 만 돌려줍니다.

```js
var BLOCKED_BIZ = ["1234567890"];   // 예시 · 실제 배포본은 [] 입니다
```

- 게이트에서 그 번호를 넣으면 입장이 막히고 **“이용이 제한된 사업자입니다. 매장(033-765-1531)으로 문의해 주세요.”** 가 나옵니다.
- 번호를 다 적고 다음 칸으로 넘어갈 때 한 번, **입장 버튼을 누를 때 한 번** DB 명단을 확인해 곧바로 차단 화면으로 바뀝니다.
- 이미 확인을 마친 손님이라도 **페이지를 열 때와 주문서를 보낼 때마다** 다시 확인해서, 명단에 들어 있으면 **즉시 로그아웃(저장 기록 삭제)** 되고 제한 안내 화면으로 바뀝니다. 주문은 Supabase·ntfy 로 나가지 않습니다.
- DB 확인이 통신 오류로 안 되면 ‘차단 아님’으로 두어, 서버 장애 때 정상 손님의 주문을 막지 않습니다.

## 사장님 화면 (`admin.html`)

- **로그인해야만 열립니다.** Supabase Auth 공용 계정(`admin@huns-fruit.kr`)으로 들어가며, 아이디·비밀번호는 코드에 없습니다. 로그인 전에는 주문·차단 명단을 **하나도 불러오지 않고** 본문도 화면에 그리지 않습니다(`body.locked`).
- **주문 목록** — 오늘/전체/새 주문/배달중/완료/취소로 걸러 봅니다. 카드마다 상호·담당자·연락처(전화 걸기)·배달주소·받는 날/시간·사업자번호·현금영수증 번호와 품목·금액·요청사항이 나오고, 번호 옆 **복사** 버튼으로 바로 복사합니다.
- **상태 변경** — `새 주문 → 배달 시작(배달중) → 배달 완료(완료)`, 진행 중 주문은 **취소**, 잘못 눌렀으면 **↩ 되돌리기**. 바꾼 상태는 DB에 바로 저장되어 다른 기기의 사장님 화면에도 같이 보입니다(손님 화면은 주문 접수 화면만 있고 상태 조회는 아직 없습니다).
- **삭제** — 두 번 누르면 목록과 DB에서 지웁니다(브라우저 확인창 없이 폰에서 누르기 쉽게).
- **차단 사업자** — 주문 카드의 **🚫 사업자 차단** 을 두 번 누르면 그 사업자번호가 `bulk_blocked_biz` 에 들어갑니다. 탭에서 목록을 보고 **해제**할 수 있고, 번호·상호·사유를 직접 적어 추가할 수도 있습니다.
- **새 주문 알림 주제** — 상단에 식자재 전용 ntfy 주제 `hoonie-dangu-bulk-914288` 과 복사 버튼이 있습니다.
- 15초마다 자동으로 새 주문을 받아 오고, **🔄 새로고침** 으로 즉시 받아 올 수 있습니다.

## 상품 사진

- 사진은 **36장**이고, 같은 품목의 다른 규격(감자 3종, 골드파인애플 3종, 안동 사과 2종, 단감·반시, 완숙 토마토 2종, 레몬 2종, 자몽 2종, 키위 3종 등)은 같은 사진을 씁니다. **사진이 있는 품목은 50개**입니다.
- 크기는 360×360, `.webp`, 한 장 5~14KB(전체 약 0.18MB)입니다. 목록에서 96px 썸네일로 보여도 선명합니다.
- 사진을 바꾸려면 `assets/img/` 에 같은 이름의 `.webp` 를 넣고 `js/catalog.js` 의 `IMG` 경로만 확인하면 됩니다.
- 사진이 없는 품목(2026-11-26 새로 늘린 54품목)은 **품목별 색 타일 + 이모지 썸네일**로 나옵니다. 깨진 사진(404) 없이 단정하게 보이도록 `css/bulk.css` 의 `.tone` 규칙을 씁니다.

## 배포 (GitHub Pages · `huns-fruit/food`)

1. 저장소 **`huns-fruit/food`** 를 엽니다. (없으면 새로 만듭니다)
2. 이 폴더의 **안쪽 내용 전체**를 저장소 최상위에 올립니다. `index.html`이 저장소 최상위에 있어야 합니다.
   - 웹에서 올릴 때: Add file → Upload files → 이 폴더 안의 파일·폴더를 모두 선택
   - git으로 올릴 때: `git init && git add . && git commit -m "식자재 주문" && git remote add origin <주소> && git push -u origin main`
3. 저장소 → Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / `/ (root)` → Save
4. 1~2분 뒤 **https://huns-fruit.github.io/food/** 로 열립니다.

사진·스크립트·스타일은 모두 **상대 경로**(`css/…`, `js/…`, `assets/img/…`)라서 `huns-fruit.github.io/food/` 처럼 하위 폴더에 올려도 그대로 동작합니다. 절대 경로(`/css/…`)나 도메인이 박힌 주소는 쓰지 않았습니다.

파일을 고쳐 다시 올릴 때는 `index.html` · `admin.html` 끝의 `?v=…` 값을 한 번 올려 주세요(지금 손님 화면은 `20261126-bulk13`). 손님 브라우저가 예전 파일을 계속 쓰는 것을 막습니다.

## 주문이 저장되는 곳 (소매몰과 완전 분리)

- 같은 Supabase 프로젝트(`hoonie-shop`) 안의 **식자재 전용 테이블 `bulk_orders`** 에 INSERT 합니다. 소매몰 테이블(`retail_orders`·`retail_claims`·`app_state`)은 **읽지도 쓰지도 않습니다.**
- 테이블 구조: `id text primary key` · `data jsonb` · `status text`(기본 `received`) · `created_at` · `updated_at`.
- 보안 규칙(RLS): **손님(anon)은 INSERT 만** 가능하고 조회·수정·삭제는 막혀 있어 다른 손님의 상호·연락처·주소가 새지 않습니다. **로그인한 사장님(authenticated)만** 전체 권한.
- `data` 안에 `channel: "bulk"`, `channelLabel: "식자재(대용량)"` 이 들어갑니다.
- 주문번호는 **`HB` + 날짜 8자리 + `-` + 6자리** (예: `HB20261126-481203`). 소매몰은 `HN`입니다.
- 새 주문 알림은 **식자재 전용 ntfy 주제 `hoonie-dangu-bulk-914288`**(`https://ntfy.sh/hoonie-dangu-bulk-914288`)로 가고, 제목은 `Hoonie Dangu BULK Order` 입니다. 소매몰 주제(`hoonie-dangu-order-914288`)와 따로 울립니다.

## 안전

- 비밀번호·관리자 키는 코드에 없습니다. Supabase에는 소매몰과 같은 공개(publishable) 키만 씁니다. 사장님 페이지의 비밀번호는 화면에서 입력한 값을 Supabase Auth 로 확인하고, 받은 토큰으로만 DB를 읽고 씁니다.
- 손님 화면은 `bulk_orders` 에 주문을 **넣기만** 하고, 주문 목록을 읽지 않습니다(RLS 로 조회 자체가 막혀 있습니다).
- 사장님 페이지는 로그인 전에 본문을 숨기고 DB 요청을 보내지 않습니다.
- 실제 주문 시험은 하지 않았습니다(사장님 알림이 가지 않도록). 처음 주문을 받을 때 사장님 화면에서 한 번 확인해 주세요.
